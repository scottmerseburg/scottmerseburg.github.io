Vertex Animation Shader

Overview and introduction

Overview

This project focuses on building a small robot driven by procedural animation instead of traditional skeletal animation. Different parts of the robot are controlled through vertex color masks, while C# sends runtime values into Shader Graph to drive movement, turning, state changes, and visual feedback.

Main components

The final setup is built around a few key systems working together.

  • Vertex Color Masks — Divide the mesh into separate animation areas
  • Shader Graph Animation — Drives shell, wheels, core, and antenna motion
  • C# Control Signals — Handles movement, turning, states, and wheel phase
  • Material Property Blocks — Send dynamic runtime values into the shader
  • State-Based Feedback — Idle, Patrol, and scan affect both motion and emissive response

Breakdown

A breakdown of the main technical parts used to build the procedural robot animation system.

Mesh masks

Vertex color channels were used to split the robot mesh into different motion zones. This made it possible to control several parts of the same mesh independently inside Shader Graph without using bones.

  • R — Outer shell / eye housing
  • G — One inner wheel
  • B — The other inner wheel
  • Combined channels — Used for inner core and extra motion logic

Shader-driven motion

Most of the robot animation is created directly in Shader Graph. Different mesh parts are rotated around custom pivots, allowing the robot to react dynamically to movement and state values at runtime.

  • Shell motion — Turning, tilt, and directional feedback
  • Wheel motion — Procedural forward and turning behavior
  • Inner core — Secondary rotation for added motion detail
  • Antenna — Bend and spring-based secondary motion

Behavior signals from C#

C# handles the robot’s behavior logic and sends a small set of control values into the shader. These values drive the procedural animation and make it easier to keep the visual motion stable and readable.

  • MoveAmount — how much the robot is moving
  • TurnAmount — how much the robot is turning
  • Antenna Bend — controls the antenna motion and adds secondary movement
  • Wheel Angle — a stable wheel rotation value calculated in code

States and visual feedback

The robot uses simple states to make the system feel more readable. These states affect both behavior, animation and emissive feedback.

  • Idle — Jittering animation, emissive feedback
  • Patrol — Patrolling movement, shel tilt, wheel spinning animation, antenna bend
  • Scan — Idle state with shell turning, emissive feedback

Rotation subgraph

This subgraph is used as the base for several of the robot’s movements. It rotates parts of the mesh directly in the shader instead of using bones or animation clips.

The setup uses a vertex position, a pivot point, and an axis to decide how a part of the robot should rotate. This makes it possible to animate different parts of the mesh in a flexible way.

  • Position — the part of the mesh that will move
  • Pivot — the point the rotation happens around
  • Axis — the direction of the rotation
  • Time and speed — control how fast the motion plays
  • Rotation amount — controls how strong the motion is

By changing these values, the same setup can be used for both continuous spinning motion and softer back-and-forth movement. This made it possible to reuse the same subgraph for multiple animated parts of the robot.

Challenges

  • One of the biggest challenges was getting stable wheel motion. Early versions relied too much on shader-only rotation, which caused flickering and snapping.
  • Another challenge was balancing movement and turning in a way that felt readable without becoming too mechanical.
  • The scan state also took several iterations to keep simple while still feeling visually distinct.

If I had more time

  • I would continue polishing the transitions between patrol, scan, and chase.
  • I would like to push the visual feedback further with more reactive emissive behavior.
  • I would also keep exploring more secondary motion to give the robot more character.
